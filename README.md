# MessagePack → JSON 使用说明

将 MessagePack 数据转换为 JSON，支持 Hex、Base64 / Base64URL、十进制字节数组和原始二进制文件。适用于查看抓包数据、过滤串口日志，以及将带包头包尾的分包按顺序拼接后解析。

[在线使用](https://chenshianovo.github.io/MessagePack-2-JSON/) · [页面源文件](./index.html)

也可以下载仓库中的 `index.html`，直接用 Chrome 等现代浏览器打开，无需安装依赖或编译。数据在浏览器本地处理，工具不会上传输入内容，也不会把输入写入浏览器存储。

## 快速开始

1. 打开页面，输入格式选择 **Hex 十六进制**，将“跳过包头”和“跳过包尾”设为 `0`，关闭“每包跳过”和“连续多条消息”。
2. 将下面的数据粘贴到左侧输入框；停止输入约 **300 毫秒**后自动解析，也可点击“转换为 JSON”或按 `Ctrl+Enter`（Mac 为 `⌘+Enter`）。
3. 在右侧查看结果，可选择 2 空格、4 空格或压缩格式，再点击“复制 JSON”或“下载 .json”。

```text
82 A4 6E 61 6D 65 A3 42 4C 45 A2 6F 6B C3
```

```json
{"name":"BLE","ok":true}
```

“载入示例”可直接体验转换。修改输入、输入格式、头尾长度或解析开关后，会自动重新解析；旧结果会先清除，避免误复制过期内容。

## 支持的输入

以下示例都表示 `{"a":1}`。Base64 和十进制数组需要手动选择对应格式。

| 输入方式 | 示例或操作 |
| --- | --- |
| 带空格的 Hex | `81 A1 61 01` |
| 连续 Hex | `81A16101` |
| 带前缀的 Hex | `0x81, 0xA1, 0x61, 0x01` 或 `\x81\xA1\x61\x01` |
| Base64 / Base64URL | `gaFhAQ==` |
| 十进制字节数组 | `[129, 161, 97, 1]` |
| 原始二进制文件 | 点击“导入二进制”，按文件原始字节读取；Hex / Base64 文本应粘贴到输入框，不能作为二进制文件导入。 |

Hex 不区分大小写，每个字节必须写满两位，例如 `0A`；支持空格、逗号、分号、冒号、连字符分隔，以及行尾反斜杠 `\` 续行。不要混入地址偏移列或 ASCII 对照列。

## 包头、包尾与三个独立开关

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 跳过包头 | `0` 字节 | 去掉数据开头指定数量的字节；作用于整段还是每包，由“每包跳过”决定。 |
| 跳过包尾 | `0` 字节 | 去掉数据末尾指定数量的字节；作用范围同上。 |
| 每包跳过 | 关闭 | 仅 Hex 可用。关闭时只去掉整段最前的包头、最后的包尾；开启时各包先去头尾，再拼接解析。 |
| 自动过滤日志 | 开启 | 仅 Hex 可用。屏蔽普通日志行，保留 Hex 数据及输入原文；关闭后严格检查全部输入。 |
| 连续多条消息 | 关闭 | 开启后将连续的多条完整 MessagePack 消息解析为 JSON 数组。它不负责识别传输分包或去除每包头尾。 |

**传输分包和 MessagePack 消息不是同一概念：**一条完整 MessagePack 消息可能分成多个传输包。此时开启“每包跳过”去掉各包头尾即可，不必开启“连续多条消息”。只有处理后的数据中确实包含多条完整消息时，才开启后者。

### 每包如何划分

连续的 Hex 行视为同一包，**普通换行不分包**。空行或被“自动过滤日志”屏蔽的日志行用于分隔数据包；没有分隔的多个包会被视为一包，需要手动在包之间加入空行。

开启“每包跳过”后，请核对输入框下方显示的包数与有效字节数。同一包内部不要插入空行或日志，否则会被分成两包；如果日志确实夹在同一包内部，应先移除该日志行并保留普通换行。工具只按粘贴顺序拼接，不根据包序号重排、不自动识别包头内容，也不验证包尾校验和。每包去头尾后至少要剩余 1 字节，否则会报错并标红。

### 示例：每包去掉头 4 字节、尾 1 字节

选择 Hex，设置“跳过包头”为 `4`、“跳过包尾”为 `1`，开启“每包跳过”和“自动过滤日志”，关闭“连续多条消息”，然后粘贴：

```text
[00:00:00.001]bt0 vendor rx:9
AA BB CC DD 82 A1
61 01 EE
[00:00:00.002]battery=68 charging=1
[00:00:00.003]bt0 vendor rx:8
AA BB CC DD A1 62 02 EE
```

这里的 `AA BB CC DD` 和 `EE` 只是示例头尾。工具识别出 **2 包、17 字节**，各去掉头 4、尾 1 后，拼接得到 **7 字节** `82 A1 61 01 A1 62 02`，结果为：

```json
{"a":1,"b":2}
```

如果关闭“每包跳过”，只会删除第一包的头和最后一包的尾，中间的 `EE AA BB CC DD` 仍会参与解析，可能导致格式错误。

### 示例：两条完整消息

头尾长度均设为 `0`，关闭“每包跳过”，开启“连续多条消息”，输入 `81 A1 61 01 81 A1 62 02`，得到：

```json
[{"a":1},{"b":2}]
```

## 日志过滤与原文定位

“自动过滤日志”会屏蔽例如 `[00:13:12.682]battery=68 charging=1` 的日志行，并提示屏蔽的行数；若时间戳后直接是 Hex，如 `[00:13:12.682]81 A1 61 01`，则保留 Hex、忽略时间戳。过滤不会改写左侧原文。疑似 Hex 的错误行仍会报错，不能区分为日志的纯 Hex 内容需要手动删除。

在右侧拖选、双击或用键盘选中 JSON 的字段名、值，左侧对应字节会以**黄色底色**显示。定位包含该值的 MessagePack 类型和长度标记，能区分重复的字段名或数字；跨包选区会跳过已去除的头尾和日志。Base64 按覆盖相应字节的编码字符定位。

未开启“每包跳过”时，字节偏移按过滤日志后的整段数据计数，保留包头所占偏移；开启后，按各包去头尾后拼接的数据计数。两种模式都从 `0` 开始，黄色高亮仍对应左侧原文。

## 错误提示与常见问题

| 现象 | 处理方式 |
| --- | --- |
| 提示无效 UTF-8、数据不完整或出现异常 Map 结构 | 检查输入是否完整，以及包头包尾长度、分包边界和粘贴顺序。多包均带头尾时，检查是否已开启“每包跳过”。 |
| 提示解析后仍有剩余字节 | 如果是多条完整消息，开启“连续多条消息”；如果是包尾或校验字段，检查跳过长度。 |
| 提示某包长度不足 | 检查头尾长度是否过大，以及同一包中是否误插了空行或日志；结果区会标红该包并显示原文行号。 |
| 数组声明数量与内容疑似不符 | 点击“定位异常”查看红色部分。工具可能给出候选数量，例如声明 3 项、推测 6 项；这只是诊断预览，需要对照协议确认，不会自动修改输入。 |
| 不能复制 JSON 或下载结果 | 当前解析失败或处于诊断预览，导出按钮会禁用；先修正输入或设置，再转换。 |
| 粘贴、复制按钮受浏览器限制 | 在输入框使用 `Ctrl+V`；复制失败时可对选中的文本按 `Ctrl+C`，Mac 使用 `⌘`。 |
| 网页仍显示旧版本 | 使用 `Ctrl+F5` 强制刷新。 |

格式检查不能识别所有业务含义错误，例如一个合法整数是否符合设备协议。“清除”会删除输入和结果、将头尾长度归零并关闭“连续多条消息”，但保留“自动过滤日志”和“每包跳过”的选择；输入区“复制”复制的是原始内容，包括日志和包头包尾。

## 特殊类型与容量

| MessagePack 内容 | JSON 中的表示 |
| --- | --- |
| 超过 JavaScript 安全整数范围（±9007199254740991）的整数 | 十进制字符串，保留完整数字。 |
| 二进制 | `{"$binary":"十六进制"}` |
| 未知扩展类型 | `{"$ext":{"type":1,"hex":"…"}}`，`type` 和 `hex` 使用实际值。 |
| 时间戳 | `{"$timestamp":{"seconds":"秒","nanoseconds":0}}`，保留实际秒数和纳秒数。 |
| 含非字符串键或重复键的 Map | `{"$map":[[键,值],…]}`，保留键值对。 |
| NaN、Infinity、-Infinity、负零 | `{"$float":"…"}` |

单次输入最多 **2 MiB 原始字节**，包含尚未跳过的头尾；最多支持 **128 层嵌套、200000 个值**。详细结构诊断仅处理 **64 KiB 以内的待解析字节数据**，更大的数据仍可正常转换，但出错时仅给出基础提示。
